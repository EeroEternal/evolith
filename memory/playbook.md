# 推理优化全流程实战十律（Evolith Empirical Playbook）

基于 Evolith 累计 **40 次真实 GPU 实验**（两个 `zstep` 源码演化归档库共 35 代候选、`Qwen3.5-27B` vLLM 5 轮验证及 57 份 8 卡微基准探针）提炼的全生命周期方法论。

- **历史实验基率**：源码级候选终审晋升率 **`17.1%`（`6 / 35` Accepted）**，单次晋升净收益区间 **`+3.72% ~ +7.83%`**。
- **82.9% 淘汰样本三大死因分布**：运行期显存/类型/状态崩溃（`~34%`）、快筛高涨但稳态全负载缩水（`~28%`）、高低并发跷跷板效应（`~20%`）。

---

## Core Laws (Prompt Digest)

> 本节由 `memory_ring.py` 自动挂载至每轮演化 Prompt 的静态前缀区，约束推理优化全过程：

1. **Amdahl 覆盖率铁律**：动手前先核验 `单算子占整步墙钟比例 × 目标负载触发率 >= 5%`；已被 `CUDAGraph` 捕获的 Host 端细碎拷贝与低触发分支属零 ROI 禁区。
2. **CPU 发射 vs GPU 活跃双轨诊断**：优化 Python/C++ 发射包装只能在 GPU 未饱和的小 Batch Eager 档位生效；高并发 `CUDAGraph` 稳态下 CPU 耗时被 GPU 队列掩盖，必须优化设备核本身。
3. **动态路由真实分布铁律**：MoE、Sparse MLA 与投机解码严禁用均匀随机张量选型（随机输入会多激活 `13%–38%` 专家），微基准必须挂载真实路由/长度分布。
4. **双模态分段分派（Piecewise Regime Dispatch）**：`M=1..16`（延迟/屏障敏感）与 `M=128..4096`（带宽/算力敏感）物理瓶颈相反，严禁单一 CTA/内核一刀切，必须显式测定切换阈值或按 `is_current_stream_capturing()` 隔离。
5. **硬件对齐甜点与 SM 预算守恒**：优先零填充对齐底层库特化 Tile（如 `b12x` `%128==64` `N64`、`128B` DDIO 缓存行）；并发双流总 CTA 不可超配物理 SM（156 SMs），否则改用单流 PDL 尾首衔接。
6. **奥卡姆减法原则**：热路径改动超 150 LOC 若净增益不足 `+3%`，立即剥离删减低杠杆包装，仅保留核心 30% 原语以消除寄存器与复杂度惩罚。
7. **100 MiB 峰值 HBM 生死线**：新增静态 Scratch / IPC Ring / Graph 分桶前必须核算最大混合步峰值显存余量，严禁在持久化 Runner 属性上悬挂中间激活张量引用。
8. **防静默缓存污染与零值哨兵碰撞**：Autotuner 缓存键必须包含完整 `(shape, dtype, runner_hash)` 且严格限制扫描目录；共享内存与状态槽位的无效哨兵永远用 `-1` 或显式 Flag，严禁用 `0`。
9. **四位一体终审锚点**：吞吐（tok/s）、首字（TTFT）、尾延迟（P99 ITL）、`0` 重编译与贪婪/异构混批数值不变性必须同时达标，且始终以 AB/BA 交错方式对比冻结的在位基线（Frozen Incumbent）。
10. **三步收敛与正交积木合体**：首轮失败往往暴露真实物理边界（显存水位、`c1` 屏障税、非 2 幂整除），应沿实测诊断做外科手术式修复，并将多个 `+1.5% ~ +2.9%` 的正交干净积木组合晋升。

## 一、 阶段一：瓶颈剖析与立项（防“假热点”与“快筛幻觉”）

### 定律 1：全链路 Amdahl 覆盖率铁律
- **实证案例**：
  - `Qwen3.5-27B` RMSNorm 微基准取得 **`1.298×`** 加速，但全模型端到端实测为 **`0.956×`**——线上 99% Decode 走带 Residual 的 `row=1` 路径，新算子实际仅命中 **`0.73%`** 调用；
  - 首轮战役 `g0002` 将 6 次小张量 H2D 元数据拷贝合并为 1 次，因本就处于 `CUDAGraph` 内，端到端 Verify 收益 **`-0.08%`**。
- **检查清单**：立项前必须在真实请求流上统计目标函数占整步 `forward_gpu_ms` 的比例与调用频次；理论端到端上限 `< 3%` 的优化直接放弃。

### 定律 2：区分“CPU 发射受限”与“GPU 硬件受限”的掩盖效应
- **实证案例**：
  - `g0016` 发现 `prefill_512` 整步墙钟 `156.1 ms` 中 GPU 仅活跃 `35 ms`（其余为 PyTorch `CustomOpDef` 装箱与 `CuTe-DSL` 参数编组），改为 C-API 直调后探针耗时下降 `-68.7%`，**Screen 暴涨 `+12.01%`**；但进入 **Verify（`c32/c128` 高并发稳态，GPU 队列满载完全掩盖 CPU 发射）** 后，净收益骤降至 **`+1.23%`** 被拒；
  - 早期投机解码草稿接受长度达 $\tau = 3.53$ 却慢于非投机基线（`246 < 312 tok/s`），根源同样是 `.item()` 主机同步与 Python 逐层发射开销，捕获进分段 `CUDAGraph` 后立即跳升至 `395–762 tok/s`。
- **检查清单**：剖析报告必须同时采集 `CPU wall-clock` 与 `CUDA Event active duration`，明确标注收益适用的并发区间。

### 定律 3：动态路由模型中“数据分布即计算图结构”
- **实证案例**：`g0017` 在常规探针与 Screen 上取得 `+9.63%`，Verify 仅 `+2.69%`；`g0018` 引入真实权重的 384 专家激活分布剖析（`realistic 384-expert routing profiling`），才定位到真正占 Decode 耗时 `55%–72%` 的窄维失配问题并拿下 **`+7.83%`**。
- **检查清单**：MoE、Sparse MLA、APC 与投机解码的微基准必须使用从真实提示词导出的激活与 `topk_ids` 快照，拒绝高斯/均匀随机输入。

## 二、 阶段二：算法与硬件映射设计（破除“高低并发跷跷板”）

### 定律 4：双模态分段分派（Piecewise Regime Dispatch）
- **实证案例**：35 代中有 7 代死于“救高并发伤单流”或“救单流伤高并发”：
  - `g0013` / `g0014`：通信扩至 56 CTAs 使 `in512_c32` 暴涨 **`+9.75%`**，但 `+16 µs` 屏障税使 `in512_c1` 退化 **`-3.09%`** 被拒；
  - `g0024`：启用 `b12x` 压缩稀疏 MLA 使 `in512_c1` 暴涨 **`+18.36%`**，但 Eager 包装开销使 `in512_c32` P99 ITL 恶化 **`+13.55%`** 被拒；
  - `g0027`：切换 `EP=2×TP=4` 使 `c32` 涨 `+2.42%`，但 `c1` 跌 `-2.85%` 被拒。
  - **通关范式**：`g0003`（`M<=64` `8×256` vs `M>64` `32×512`）、`g0018`（`M<=16` 1-Shot / `M=32` 8-CTA / `M>=128` 56-CTA 全双工）、`g0025`（仅在 `is_current_stream_capturing()` 启用新 MLA 核）。
- **检查清单**：任何算子或通信改动必须分别评估 `M=1`（延迟敏感）与 `M=2048..3072`（吞吐敏感），显式设置分段路由阈值并通过 `dispatch_verifier` 完备性校验。

### 定律 5：硬件对齐甜点（Sweet-Spot Padding）与物理 SM 预算守恒
- **实证案例**：
  - `g0018` 将 `TP=8` MoE 窄维 `I=288`（`288 % 128 == 32`）零填充至 **`I=320`（`320 % 128 == 64`）**，精准激活 `b12x` 紧凑 `N64` Tensor Core 特化核，零精度损失削减整步 Decode 耗时 **`13.9%–17.6%`**；
  - `g0015` 对齐 `128B` Xeon DDIO 缓存行边界，消除跨缓存行分裂写；
  - `g0018` 与 `g0021` 证明在 156 SM 的 RTX 6000D 上，56-CTA 通信核与副流高 CTA `mHC` 核并发会争抢 SM（`M=32` 每步反慢 `+0.24 ms`）。
- **检查清单**：重写算子前先对齐现有高性能库的指令分块甜点；计算-通信重叠若总 CTA 超出物理 SM，优先采用单流硬件级 PDL 尾首重叠而非多流硬抢。

### 定律 6：奥卡姆剃刀与减法工程
- **实证案例**：首轮 `g0007`（`280 LOC`）因复杂图内解包与盲目扩预算在 Verify 失败（`net_gate=0.9923`），`g0008` **删去近 100 行代码（`182 LOC`）** 后以 **`+5.67%`** 全指标通过；第二轮 `g0021`（`200 LOC`）因超出免费行数被扣除约 `-1.6%` 净分。
- **检查清单**：保持补丁聚焦单一物理机制，优先控制在 `complexity_free_lines`（`<= 120–180 LOC`）以内。

## 三、 阶段三：编码实现与系统卫生（避开线上崩溃与隐性退化）

### 定律 7：峰值 HBM 余量硬预算（100 MiB 决定生死）
- **实证案例**：`g0001`、`g0002`（Screen `+6.03%`）仅因 4-slot IPC Ring 多占 `~117 MiB`，在 Rank 6 差 **`2.2 MiB`** 分配不出 Engram `200 MiB` `all_gather` 临时块而 OOM；`g0007` 因包装类多保留一个绑定张量引用触发 Warmup OOM；`g0003` 缩至 2-slot Ring 释放 `+117.5 MiB` 立即通过。
- **检查清单**：所有持久化 Buffer、新增 `CUDAGraph` 桶与自定义分配必须通过峰值显存核算，并在初始化阶段彻底释放临时引用。

### 定律 8：警惕 Autotuner 缓存键污染与 `0` 值哨兵碰撞
- **实证案例**：
  - `g0014` $\rightarrow$ `g0015` 查明二次启动 `M=1` TPOT 恒定变慢 `0.32–0.52 ms` 的元凶：`_load_flashinfer_autotune_cache()` 扫描了整个 `~/.cache`，误读剥离 `runner_hash` 的旧缓存导致恒定假命中劣质 `runners[0]`；收紧至 `~/.cache/flashinfer` 后直接以 **`+7.76%`** 晋升；
  - POSIX SHM 默认全 `0` 曾使未启用 APC 时的 `compressor_slot_ids == 0` 误触发状态覆盖；非 2 幂分桶（`rows=24, blocks=32`）曾因 Python/C++ `eff_blocks` 不一致触发 `blocks % rows == 0` 整除断言崩溃（`g0004`、`g0009`），以及因 `all_reduce`（`<=10240`）与融合 `all_reduce_add_rmsnorm`（`<=40960`）的 `small_pxb` 阈值不一致破坏 `control` 双网格步调锁步（`g0010` `main lockstep broken`）。
- **检查清单**：缓存键必须包含 `runner_hash` 与精确 Shape；跨进程/共享内存无效槽位一律初始化并校验为 `-1`；网格映射必须覆盖中间非 2 幂次分桶（`24, 48, 96`）。

## 四、 阶段四：评测门控与迭代收敛（高确定性拿到终局突破）

### 定律 9：吞吐 + 尾延迟（P99 ITL）+ 零重编译 + 冻结在位锚点四位一体
- **实证案例**：
  - `g0007` 与 `g0006` 证明忽略 `p99_itl_ms`（恶化 `+6.97% ~ +9.44%`）会放过严重卡顿的调度改动；
  - 早期无人值守实验曾出现“破坏 `--speculative-method none` 基线 `CUDAGraph` 使基线暴跌 `-29%`”的奖励作弊，被冻结在位基线（Frozen Incumbent）机制彻底根治；
  - `Qwen3.5` `w4-r1` 初测 `1.049×`、独立种子复测 `0.995×`，证明单轮非交错测量极易受温度/频率漂移欺骗。
- **检查清单**：终局准入永远采用多轮 AB/BA 交错对比当前已批准在位版本，同时卡死单档吞吐回退、TTFT/TPOT/P99 ITL 回退、`CV <= 10%` 与 `TRITON_RECOMPILATIONS == 0`。

### 定律 10：遵循“三步收敛律（Probe $\rightarrow$ Stumble $\rightarrow$ Surgical Fix）”与正交合体
- **实证案例**：全部 6 次成功晋升均经历 **2–3 代针对性打磨**而非首版盲中：
  - `g0001 (OOM)` $\rightarrow$ `g0002 (OOM)` $\rightarrow$ **`g0003 (+3.72% Accepted)`**
  - `g0009 (整除报错)` $\rightarrow$ `g0010 (10240 vs 40960 锁步断裂)` $\rightarrow$ **`g0011 (+5.19% Accepted)`** $\rightarrow$ **`g0012 (+5.93% Accepted)`**
  - `g0013 (c1 退化)` $\rightarrow$ `g0014 (缓存污染)` $\rightarrow$ **`g0015 (+7.76% Accepted)`**
  - `g0016 (CPU/GPU 错位)` $\rightarrow$ `g0017 (路由失真 +2.69%)` $\rightarrow$ **`g0018 (+7.83% Accepted)`**
- **检查清单**：当高潜力方向首轮因单一边界指标（如显存差几 MB 或 `c1` 轻微退化）被拒时，优先做针对性外科修复而非轻易抛弃方向；当两个独立子系统的干净优化各自稳定在 `+1.5% ~ +2.9%`（如 `g0025` Decode MLA Graph `+2.88%` 与 `g0021` AllGather 压缩 `+2.88%`）时，通过正交叠加合体冲线。
